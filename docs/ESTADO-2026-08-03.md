# Yunkil: estado de cierre

Fecha: 3 de agosto de 2026.

## Producto utilizable

- Aplicación macOS en `build/Yunkil.app`.
- Inicio en una esfera editable sobre plato milimétrico.
- Modo `Crear` para usuarios sin experiencia y modo `Taller` avanzado.
- Creación mediante prompt o asistente guiado por tres preguntas.
- Primitivas, booleanas, modificadores, transformaciones, duplicado y undo/redo.
- Exportación STL con resolución, progreso y certificado legible.
- Icono propio integrado en bundle, Dock e interfaz.

No existe todavía una aplicación iPad terminada. El núcleo Kotlin puede compartir
código con iOS, pero la interfaz actual es macOS.

## IA

La UI permite elegir:

- `Local privado`: modelos descubiertos desde Hearthia en `127.0.0.1:9292`.
- `OpenCode Go`: modelos compatibles con Chat Completions o Messages.

La selección queda guardada por proveedor. OpenCode Go reutiliza la credencial ya
conectada en OpenCode sin mostrarla ni copiarla a la configuración de Yunkil.

Garantías actuales:

- Solo se aceptan acciones declarativas `add` y `wrap` y tipos conocidos.
- Se normalizan sinónimos frecuentes en español e inglés.
- Máximo de 40 acciones y magnitudes finitas/acotadas.
- Un plan inválido se reintenta una sola vez con diagnóstico concreto.
- La propuesta requiere confirmación antes de modificar el documento.
- Cancelar o fallar durante la aplicación restaura el JSON anterior.
- `crear/hacer/diseñar` puede reemplazar el documento; `añadir` lo conserva.

Prueba real de cierre:

```text
Proveedor: OpenCode Go
Modelo: DeepSeek V4 Pro
Petición: haz un cono de trafico
Resultado: UNION:Modelo, CONO:Cono de tráfico, documento no vacío
```

El error anterior estaba en la integración: `Editor` devuelve `false` cuando una
edición válida solo cambia uniforms y no recompila el shader. Ya no se interpreta
como fallo; se comprueba `ultimoError`.

GPT 5.6 Luna no está expuesto todavía porque OpenCode Go lo sirve mediante la API
Responses, distinta de las dos rutas implementadas.

## Exportación y seguridad

- Resolución obligatoriamente positiva y finita.
- Rechazo preventivo por encima de 250 millones de celdas estimadas.
- Cada arista debe tener exactamente dos incidencias opuestas.
- Índices inválidos, vértices no finitos y triángulos degenerados se rechazan.
- Se comprueban orientación, volumen positivo, error de volumen y desviación.
- El STL se escribe a temporal y se renombra: un fallo no deja un archivo parcial.
- Los documentos guardados conservan copia `.bak` al sobrescribir.

La revisión estricta descubrió que el antiguo soporte de demostración combinaba
cáscaras que producían una malla no manifold. No se rebajó la comprobación; se
replanteó el ejemplo para producir un sólido válido.

## Rendimiento

- Raymarching Metal con degradación térmica ya existente.
- El plato de impresión se calcula analíticamente en el fragment shader.
- La altura del plato se actualiza al cambiar documento, no en cada frame.
- El mallado recorre láminas y evita mantener una rejilla 3D completa en memoria.

## Verificación


firmada ad-hoc y abierta correctamente.
